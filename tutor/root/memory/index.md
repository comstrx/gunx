# Memory

## Contract

Memory is a thin session and machine wrapper over Tutor, never a second skill library.

## Structure

- Durable memory index: pointers and one-line purpose, not copied laws.
- Session state: current goal, primary role, focus, scope, constraints, selected knowledge, progress and unresolved decisions.
- Workspace notes: relevant paths and dated observations; no secret values or copied operating procedures.
- Pending decisions: owner words not yet reflected in their responsible skill, with provenance and status.

## Rules

- Bootstrap memory may point to Tutor; stale memory cannot overrule the current owner instruction or verified skill.
- Re-derive the active request after compaction. Reopen entry/root and selected changed or no-longer-recalled skills before further action.
- Keep session knowledge scoped. A request to study project knowledge does not authorize reading unrelated messages or historical records.
- A directory listing discovers names, not permission to open every file. Whole-project knowledge means registered guides, not arbitrary newly created messages.
- The same path in a different project copy is a different workspace. Never transplant live IPC paths, permissions or implementation facts blindly.
- Versions belong in manifests, business in product skills, reusable engineering in its skill, transcripts in history; do not duplicate.
- Correct stale observations within authorized memory; distinguish observed, desired, approved, deferred and unverified. Root/work owns history access and skill-edit authority; memory stores approved pointers.
- Do not record provisional suggestions as permanent policy. Do not convert an example or agent proposal into an owner decision.
- Write only within authorized memory scope. A "do not execute" instruction includes memory edits.
- Store no credentials, personal datasets, raw customer payloads or entire prompts where a minimal reference suffices.

## Proof

A new session can recover its role and source pointers without inheriting unrelated assumptions or re-reading every prior transcript.

## Sources

Owner memory design; applicable host memory instructions.

## Routing

Return to the calling root entry after study.
