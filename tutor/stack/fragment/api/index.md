# api

`product/<project>/api` is a product's backend: a workspace of services, each a Laravel-shaped application over the Rust or the Python engine (the client's choice, named by the workspace manifest; nothing else about the product changes). Microservices by default, DOMA: a `gateway`, an `iam`, and one service per business domain, a domain owning every table that serves one business logic (never a service per table), meeting through one contract. A monolith only when the client asks for it in so many words, and then it is the same layers in one service.

## Layout

```
product/<project>/api/
├── pyproject.toml  uv.lock   the workspace root `api` (`package = false`, members = ["src/*"], depends on every member): one lock, one ruff, one mypy, one pytest, the engine by path
├── src/<member>/             one member, the engine's shape: pyproject.toml (`api-<member>`: the engine domains and `api-contract` it imports, by name) and src/<member>/ (the package, py.typed)
│   ├── contract/             the shared vocabulary: app/{enums, models} (roles, audiences, services, boundaries, topology), config/{scopes, services}, resources/messages (the codes and the shared reasons, en and ar, as `MESSAGES`)
│   ├── gateway/              the one external door: doors per audience, the relayed identity, edge limits, proxying, the gathered OpenAPI
│   ├── iam/                  accounts, one-time codes, sessions (code, start, refresh, end): the first service every other one trusts
│   └── <service>/            .env.example (committed: every setting), .env.local and .env.production (ignored), pyproject.toml, and src/<service>/:
│                             app/{commands, controllers, repositories, services, models, requests, resources, enums, events, jobs, middlewares, listeners, mails, utils/{dna, cycle/{model, repository, resource, service, controller, request, route, middleware, event, job}}}
│                             bootstrap/app.py (`make`, the only wiring), config/{app, topology}.py, database/{migrations, seeders}, routes/{api, channel, events, schedule}.py
│                             public/robots.txt, resources/{messages, views, assets}, storage/{app/{public, private}, logs}, __main__.py
├── tests/                    flat test_<member>.py, test_journey.py (every service booted on real ports through the gateway), test_laws.py
└── benches/                  flat bench_<member>.py on the engine's bench
```

No script beside the tree: the stack runs through the infrastructure engine, and a `*.sh` in a product part is refused.

## Laws

- **Topology:** every service names its layer; calls go to a smaller layer, committed events go to a larger one; no cross-service SQL, model import or foreign key; every boundary states actor, scope, input and output shape, expected revision, idempotency identity and failure meaning in `config/topology`; no unused wildcard access; events are named `<producer>.<fact>`.
- **One owner:** one service owns each responsibility and its database; money has one owner, in integer minor units on a balanced immutable ledger; a new offering, worker or model server never creates a new service.
- **Gravity:** engine → `utils/dna` → `utils/cycle` → migration → model → repository → resource → service → controller → request → route, each layer a few lines over the one beneath it. A model is a thin declaration over its migration (`table`, `fillable`, `hidden`, its own small verbs such as `User.actor()`); a repository is one query chain per function and the only maker of models (`make`, `compose`); a resource shapes a model for the wire (`fields`, or `dump` when the shape is computed); a service is a readable pipeline over repositories and engine verbs and answers with resources, never with a model; a controller is one line over its service and answers through `ok created accepted empty page json`; a request is the input layer: a `cycle.Request` (an `http.Form`) with typed fields, `rules` and their `reason`, `prepare`, and `carries` (`locale principal actor bearer fingerprint client trace request`), bound to its action by `Request.to(controller.action)`, so the controller receives clean values and never the raw input; a route binds a request (or, for raw doors such as the gateway's, a controller handler) with its guards, throttle and middleware. `utils/dna` is what every model inherits (a `validate.Shape`: `fillable`, `hidden`, guarded `fill`, `dump`, then the product's relations, morphs, search, permissions, attachments and media); `utils/cycle` is the service's lifecycle bases, one file per layer, each one line over an engine base: `Model(Dna, database.Model)`, `Repository(database.Memory)` or `Repository(database.Repository)` (`run` and `ready` are the engine's), `Resource(validate.Resource)`, `Request(http.Form)`, `Middleware(http.Layer)`, `Event(event.Signal)`, `Job(queue.Work)`, `api(name, *routes)` = `Group.of("", *routes, name=name)`; only `Service` (`rows`, `resource`, `show`, `index`, `run`) and `Controller` (`service` and the answers) carry lines of their own, because they are the product's pipeline. A service moves to PostgreSQL by changing `cycle/repository.py` to `database.Repository`, nothing above it. `bootstrap/app.py` is the engine's setups (`log`, `metrics`, `translate.load(MESSAGES, ROOT / "resources" / "messages")`, `token`, `auth`) and one chain: `App(name, version).throttles(…).routing(routes(…)).public(ROOT / "public").lifecycle(rows.run, service.run)`; `routing` also serves `/health` and `/ready`, and the `App` records the service and its version. `config/app.py` names `ROOT`, the package, and loads its member's `.env.<stage>` before the settings. When a layer needs more, the more is an engine verb.
- **Layer** (test, over the `ast` of every relative import): `dna` reaches nothing of the service; `cycle` only `dna`; a model only `cycle`, `dna`, its migration and the enums; a repository only models, `cycle` and enums; a resource only models, `cycle` and enums; a service only repositories, resources, `cycle` and enums; a controller only services and `cycle`; a request only controllers, `cycle` and enums; a middleware only services and `cycle`; a route only requests, controllers, middlewares and `cycle`; a seeder only models and enums; `config` nothing of the service; only `bootstrap` reaches every layer.
- **Workspace** (test): every member is `api-<dir>`, declared once as a workspace source and a root dependency, and declares exactly the engine domains and `api-contract` it imports.
- **Domain** (test): a member imports only the engine, `contract` and itself; a service never reaches a sibling service.
- **Layout** (test): a member holds only `.env.example .env.local .env.production pyproject.toml src`; its package only `app bootstrap config database public resources routes storage` beside `__init__ __main__ py.typed`; `app/` only the fourteen layers, `utils/` only `dna` and `cycle/` with its eleven files, `resources/` only `messages views assets`, `storage/` only `app/{public, private}` and `logs`; a member builds only the layers it uses. A service carries `bootstrap/app.py config/app.py routes/api.py __main__.py public/robots.txt resources/messages/{en, ar}.json`, its storage leaves and `.env.example`; `contract` carries `app config resources` and never boots.
- **Env** (test): `.env.example` names exactly the keys of the service's settings, secrets empty; `.env.local` and `.env.production` stay on the machine, and a secret left empty is refused in production.
- **Message** (test): every reason a member raises has its English and Arabic in the member's or the contract's `resources/messages`, and the envelope speaks the request's language.
- **Import** (lint): layers import only the engine, the contract and the service; ruff `banned-api` refuses every library the engine wraps anywhere above the engine, benches' clients aside; beyond typing, data classes and collections the stdlib is reviewed; handlers answer `http.Answer`.
- **Migrations:** one file per table with all its constraints and indexes, forward only, no `down`; before production a table's own file is rewritten, never patched; a constraint for every invariant, partial uniques for live rows, an index on every reference, filter and sort a real query uses and none a query does not; timestamptz, jsonb where it earns its place, exact money. A table is a `database.Table` declared in `database/migrations/<table>.py`, the member's `TABLES` tuple plus its outbox (`Outbox.blueprint`), inbox (`Events.blueprint`) and ledger (`Migrator.ledger`) are applied by the engine's migrator in the service's `bootstrap` at boot, inside the service's own schema (`<SERVICE>_DATABASE_SCHEMA`, created by the same boot) on the service's own `Database()`; a row policy beyond tenant isolation is declared on the table (`policies=[(name, expression)]`) and reads its setting through the dialect (`POSTGRES.setting("user")`), never through a bare `current_setting`, because a reset session value is an empty string, not NULL.
- **Reads and writes:** no N+1; bounded lists with cursors where tables grow; selected columns on hot paths; cache with a key, TTL and invalidation and stampede protection; short transactions with no network call inside; business mutation and outbox in one local transaction; uniqueness races settled by the database; `skip locked` for claims.
- **Security:** under `ENGINE_ENV=production` every service refuses its lab secrets and addresses, and the journey pins each refusal; identity crosses from the gateway to a service only through the engine's relay, read by `auth.relay.guard(scope)`; actor and scope from the relayed identity; an ended session is refused at the edge and by every `auth.guard` through the engine's revocation list (`auth.revoke(jti)`, `auth.revoked`), shared through `cache`; the database link is verified TLS unless the host is loopback (`<SERVICE>_DATABASE_SSL` overrides, the engine refuses an unknown mode); no IDOR, mass assignment or enumeration; a rate limit that fits each route class; signed webhooks; masked secrets; internal doors stay internal; a path parameter reaches an upstream only through `net.segment`; the api is reachable only from the edge.
- **Reliability:** bounded timeouts, retries and breakers on every peer call; handlers safe for duplicates and disorder; scanners for what a crash leaves; no state leaking between requests or jobs.
- **Contract:** generated OpenAPI truthful for every route, gathered at the gateway per audience; every reason with its code and both languages.
- **Providers:** every external provider is an engine adapter with a mock or sandbox; a product may ship on mocks until its first full release by the owner's word.
- **Proof:** races where money, stock or uniqueness are at stake; journeys walk every business path through the real stack; the suite's `conftest.py` drops every service schema once per run so a test never inherits rows, and a test that needs a user no other test touches names one from the seeds.

## Gate

`infra gate --part api --product <p>`: the chain of the engine the root manifest names, over the whole workspace, minus `audit` and `fuzz`; tests and benches only.

## How to add

- **A service:** from the skeleton (`utils/{dna, cycle}`, configs and `.env.example`, messages, `public/robots.txt`, storage leaves, outbox and inbox migrations, routes, health and spec tests), a row in `contract`, a layer, its topology, a database of its own.
- **A feature:** enum → migration → model → repository → resource → service → controller → request → route → test → bench when hot → the surfaces' `reply.md` when a contract changed.
- **An engine capability:** never here; in the engine with its test, then consumed in one line.

## Direction

Laravel's shape, thinner than Laravel, over an engine that carries responses, faults, contracts and the whole lifecycle: a `bootstrap/` that is the only wiring point, a `config/` of settings groups, a command line as the manual, declarative tables when the engine's migrator lands, and services that an engineer of the framework reads at first sight. The same layers in Rust and Python, so a product can change language without changing shape.
