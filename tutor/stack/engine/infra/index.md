# engine/infra

The general engine of the work: one self-contained Bash 5 bundle that is at once the framework (`core` as a standard library, `config`, plug-and-play modules, the `@` macros), the tool of this repository (build, check, test, bench, fuzz, audit, the gates of every part, the `.github/` that travels, the extraction and the mirrors) and, tomorrow, the infrastructure (a Linux or macOS box from nothing to a running, monitored, backed-up stack, deployed without downtime, declared under a `[deploy]` scope of `infra.toml`, never as a meta of the tool). Written once for every product; every Bash script of the repository lives here. `product/<project>/infra` customizes it with data and may extend it over its entry (`stack/fragment/infra`). Written in `language/bash`. Gate: `bash src/main.sh setup infra`, `bash src/main.sh check`, `bash src/main.sh test`, `bash src/main.sh audit`, `bash src/main.sh fuzz <seconds>`; `bench --compare` judges the baseline. The DSL is `{layer}:{domain}:{verb}` with no floating name: every function is prefixed, and the only short hands are the `@` macros of the bundle; see `language/bash`.

Every layer has one `index.sh` facade and every module one; `core:load:use core::fs` (or `@use core::fs` above the bundle) loads `core/fs.sh`, `module::gate` loads `module/gate/index.sh`, `config` loads `config/index.sh`: a name resolves to the file, else to the folder's `index.sh`. A facade holds no function; `app/index.sh` holds the entry only.

**Macros.** `module/bundle/src/macro.sh` is one thin file of global macros, loaded with the bundle before every other module: `@use @print @debug @info @succ @warn @err @usage @flag @global @eq @contains @absent @fails @errors @status @measure @tool @fetch`. They are a layer over the real verbs, never a replacement: `core:log:succ` or `module:bundle:usage:add` stay callable. The modules (`gate extract`), `app/` and the proofs write with them; `core/`, `config/` and the bundle module itself never do (they sit below them). ShellCheck cannot parse a `!` in a name, so the macro mark is the leading `@`.

## Laws

Enforced by `check` on every source and test file:

- **Names:** every function is `{layer}:{domain}:{verb}` (a verb may carry more segments: `core:fs:file:read`, `module:bundle:law:check`); the layer and the domain come from the path (`src/core/fs.sh` → `core:fs`, `src/module/ci/src/yaml.sh` → `module:ci`, `src/app/gate.sh` → `app:gate`, `src/app/index.sh` → `app`); `core`, `config` and `app` are flat, a module is `index.sh` + `src/` + `template/`; a proof file is named by its suffix (`.test.sh .bench.sh .fuzz.sh`) and holds `test:* fixture:* bench:* fuzz:*` only; `#cfg[test|bench|fuzz]` on the line above a function in `src/` makes it a proof (the only comment the laws accept); no name floats: the only unprefixed functions are the `@` macros of `module/bundle/src/macro.sh`; a name is defined once.
- **Layer calls:** ranks `core < config < module < app < proofs`; a function calls its own layer and the layers below, never above (a module calls core, config and sibling modules; app calls everything); a called `{layer}:…` name must exist (a dynamic `"module:gate:${part}"` is checked to its prefix); `main.sh` calls `app:main` only. A tool combining two others belongs in app.
- **Portable:** Linux and macOS are one target: `uname`, `stat -c|-f`, `sha256sum|shasum`, `timeout|gtimeout`, `shuf|sort -R`, `kill -0 || ps -p` (a process of another user is alive too), a `mkdir` lock (no `flock` on macOS) are decided inside core; outside `core/` the laws refuse `sed -i`, `shuf`, `readlink -f`, `date -d`, `grep -P`, a bare `timeout` and a bare `sudo` (call `core:fs:file:edit`, `core:list:shuffle`, `core:process:timeout`, `core:sys:sudo`); the `global` and `infra` workflows run on ubuntu and macos; `setup infra` installs the runtime commands of `[requires]` through the machine's package manager when they are missing, with `sudo -n` only (never a prompt).
- **I/O:** every network call runs through `core:process:io` (retries with backoff under a timeout, `RUN_TIMEOUT RUN_RETRIES RUN_BACKOFF`); every test runs under `TEST_TIMEOUT`; `bench --compare` fails past `BENCH_TOLERANCE` over the saved baseline.
- **Parts:** only `config/` and an env schema name a part; a source, test or template that writes a part's key prefix fails the check; tests run on their own fixture table. The engine never names a product; a product's repository, name and paths are rows in the distribution table.
- **Values are data:** config resolves once with a fixed precedence (`infra.toml`, then `Infra.toml`, then the env files, then the command line), unknown keys fail atomically; nothing becomes executable.
- **Secrets:** names matching `PASSWORD SECRET TOKEN CREDENTIAL WEBHOOK_URL _KEY` are redacted everywhere; every integration turns on only when its keys exist, all or none, behind neutral keys.
- **The bundle** embeds every source and asset byte for byte into `target/`; a test compares each embedded asset with its file; the release bundle carries a checksum; it is slimmed (every `#cfg[…]` block, blank line and indentation of the sources gone, assets byte for byte) and never compressed: a compressed bundle would have to execute a decoded value, which the laws refuse, and ShellCheck, `audit` and a reader could no longer see it.
- **Delivery:** images are built from the repository root, scanned and pinned by digest; deploys are blue/green with draining, a verify window and automatic rollback; migrations are a release of their own, never at peak and never in the same breath as the code deploy; backups with point-in-time recovery and a rehearsed restore before every release; the api reachable only from the edge; only content-hashed files served immutable; every alert has an owner and a recovery action.
- **Env ownership:** each product part owns its env file and nothing crosses; the engine receives it, pins it and mounts it read-only, forcing only what it owns (bind address, port, storage root, migrations off, release name). Application policy belongs to the app env and the app enforces it.
- **Standalone:** `install --alias gun` builds the release bundle and writes it as a command (`~/.local/bin` or `XDG_BIN_HOME`); run from any project root it reads that root's `infra.toml` (`[tool.*]` there first, the embedded table otherwise) and its git tree, so the same bundle serves this monorepo or any project shaped like it; `targets` and `sync` refuse to run while a target's part is missing under the root (every missing one named, nothing pushed), and refuse an empty table.
- **Sync:** the distribution is steps, each a verb, composed by commands. `prepare` lists the tree with `git ls-files` (nothing ignored travels), keeps by kind (engine: `engine/<x>`; fragment: `product/<p>/<f>`; tutor: `tutor/` minus `stack/product/*`; product: everything minus the other `product/*` and `tutor/stack/product/*`), flattens a tool to its root, adds the root governance files (`.*`, `LICENSE`, the four community docs with the monorepo's name renamed to the tool), cuts the changelog to the part's blocks and strips `[deps]` from `infrax`. `verify` refuses the monorepo's name and every product's name (read from `product/*`) in any tool, a `../` path into `engine/ product/ tutor/`, an env file and a tree without a manifest at its root; the renamed community docs are re-formatted by the pinned Prettier so their tables stay aligned. `gates` runs the default gate chain of the part inside the prepared tree (`module:gate:one`, the one cross-module call, from `extract/src/gate.sh`), each type under `--timeout` (1800 s by default); a failure stops the steps after it. `extract NAME [--into DIR] [--gates]` = prepare + verify (+ gates) into a kept session tree under `.infra/run/<stamp>/sync/<name>` (every run of the tool works in one stamped session folder of the lab, removed at exit unless `extract` kept it) or `DIR`; `place NAME DIR` = extract, then write into a local folder keeping its `.git`; `push NAME [--branch B] [--repository R] [--dry-run]` = prepare, then `module:extract:git` does the rest: the address of the table (or `--repository`) is resolved by `core:git:resolve` (`name` → the owner and host of the current tree's `origin`; `owner/name` → that host; `host/owner/name`, an `https://`, `ssh://` or `git@host:` URL, or an absolute path, taken as given); a repository that does not exist is created private (`gh repo create` when `gh` is logged in and no `GIT_TOKEN`, else the GitHub API with `GIT_TOKEN`; a path becomes a bare repository); the branch is cloned (an orphan branch when it is new), emptied but `.git`, filled with the tree, verified and gated in place, committed `Track <tag>` (the target's `tag` when it is a semver, else the exact `v*` tag of HEAD, else its short sha) on top of the mirror's history (no commit when nothing changed, never a force push), tagged (an existing tag refuses), then pushed; `--dry-run` stops right before the push, authenticated by `GIT_TOKEN` (or the token of the logged-in `gh`, never on argv) and committed as `GIT_CONFIG_NAME <GIT_CONFIG_EMAIL>` or, when either is unset, as the author of the last commit of the source tree (the mirror carries the name of whoever pushed the monorepo); `sync` pushes every target of `[deps]`, the infra engine first. Locally `--gates` is a choice; CI passes every flag.
- **`.github/` travels (stronger than the SaaSX extraction it replaces):** a tool receives `CODEOWNERS`, the issue and pull request templates, `labels.yml` and `labeler.yml` (every part label dropped, the generic ones kept), `dependabot.yml` (the actions entry and the tool's own ecosystem entry moved to `/`, prefixes `deps`, the monorepo header gone) and every workflow (`ci bench fuzz release labels labeler`). `module:extract:flows` rewrites them in place through `core:parse:yaml:*`: `paths:` filters erased (a tool is its whole repository), the job that runs `infra sync` pruned, `*-version-file: engine/<x>/<file>` pointed at the root file when the tool has it and dropped otherwise, empty `with:` blocks removed, `uses: $/engine/infra/src/module/gate/template` rewritten to `<owner>/infrax/src/module/gate/template@<sha> # <tag>` (the sha of the infrax mirror at the release tag, else its `main`; `$/src/module/gate/template` inside infrax itself) and that action allowed in the tool's `.zizmor.yml`; the monorepo's name (the name of the root's `origin`, never a literal) becomes the tool's name in `.github/**` and the community docs; Prettier re-formats what was renamed; `verify` then refuses any `engine/ product/ tutor/` path or `main.sh` under `.github/`. A product keeps `.github/` whole, minus the Dependabot entries of the other products. Every extracted tool passes actionlint and zizmor (pedantic, low) offline.
- **Gate:** `gate [--part P] [--product X] [--type T] [--timeout S] [--pass]` is the one gate command, for every part (`rust python go bun infra api web mobile desktop tutor global`; every part present under the root when `--part` is absent), in the part's folder (`engine/<x>`, `tutor`, the root, or `product/<X>/<fragment>` where `--product` defaults to the first product; a tool root is the product `.`). The types are `deps check lint test safety audit quality security bench fuzz`; `--type` is `default` (`deps check lint test safety audit quality security`, never bench or fuzz), `all`, or a comma list; a type a part does not have is skipped. Every type is one function `module:gate:<chain>:<type>` in `gate/src/<chain>.sh` with the full command inlined (no `cargo xtask`, no `bun run gate`: the chains are the truth): `rust` (rustup with miri and rust-src + binstall of the cargo tools; `check` + `hack --feature-powerset`; clippy `-D warnings` + rustdoc `-D warnings`; nextest + doc tests; `safety` = nightly udeps + miri + the address sanitizer over `-Zbuild-std`; deny + vet + semver-checks against the last `v*` tag; `cargo bench`; `cargo fuzz` per target under the budget), `python` (`uv sync --locked`; mypy; ruff; pytest; `safety` = pytest again under `PYTHONDEVMODE PYTHONMALLOC=debug PYTHONWARNINGS=error`; pip-audit over the frozen export; `benches/*.py`; `fuzz/*.py`), `go` (golangci-lint and govulncheck at their pins; `tidy -diff` + vet over every module; `test -race -shuffle`; `safety` = `test -asan` on linux with a C compiler, skipped elsewhere; `-bench`; `-fuzz` per target), `bun` (`install --frozen-lockfile`; `tsc`; `biome ci`; `bun test tests`; `safety` = the tests again under `bun --smol`; `bun audit`; `benches/*.bench.ts`; `bun test fuzz`), `infra` (the runtime packages + `fetch shellcheck` inside the gated tree; `check test audit bench fuzz` of this engine; `safety` = `test --shuffle`), `tutor` (typos + Prettier), `global` (the six scanners fetched at their pins; `security` = gitleaks dir, trivy fs, syft SBOM into `target/`, zizmor pedantic/low; `quality` = typos, taplo, Prettier); `api` picks its chain by manifest (`pyproject.toml` python, `Cargo.toml` rust, `go.work|go.mod` go; never bun), `web mobile desktop` are bun. Each type runs in a subshell under `--timeout` (1800 s by default; a fuzz or bench splits nine tenths of it over its targets, `GATE_SECONDS`), a timeout is reported as such; `--pass` reports a failure and goes on (the daily bench and fuzz). `changes [--base REF] [--all]` (or `CI_BASE`, `CI_ALL=true`) prints `matrix=[{ part, product, os }…]`, one row per gate to run (an engine when its folder moved, `tutor`, `global` when a root file or `engine/infra` moved, a product fragment when it was touched, when `engine/infra` moved or when the engine its manifest names moved; `infra` and `global` on ubuntu and macos; `--all` lists everything) and writes it into `GITHUB_OUTPUT` when it exists; the logic is tested offline and a workflow never carries a script.
- **Extension:** a product's `src/main.sh` sources this engine's `src/main.sh` with `INFRA_ENTRY=library` (no dispatch), then defines its own `app/` over the same core, config and modules under the same laws; the product's `check` runs the engine's laws on the product's files too.

## How to add

- **A core verb:** `core:<domain>:<verb>` in `core/<domain>.sh`, general as a standard library, silent on success, `core:error:fail` on failure, a `test:core:<domain>:*` case in `tests/`; never a proof inside `core/`.
- **A module:** `module/<name>/index.sh` that `use`s `module/<name>/src/*.sh` (`module:<name>:*` over core, config and the bundle only; thin pipelines; `check` refuses a call into another module) with its data under `module/<name>/template/`; a `test:module:<name>:*` case; nothing else changes.
- **A command:** one line in the module's `src/usage.sh`: `@usage NAME HANDLER 'usage' 'summary'` (+ `@flag NAME '--flag VALUE' 'summary'`); the help, the flags and the dispatch follow; a handler is a module verb.
- **A gate type or chain:** one function `module:gate:<chain>:<type>` in `gate/src/<chain>.sh`; `run` discovers it.
- **A sync target:** one line in `[deps]` (`name = { type, path, repo, deps = [...] }`; `tag` only when it is not `inherit`), a product's `repo` in its own `[meta]`; `sync` reads the line and runs the same `prepare → verify → place|push`.

## Direction

From the needle to the rocket by one bundle and one command: install the newest tools, configure the services, run and monitor them, manage ips, domains and TLS, back up and restore with point-in-time recovery, roll blue/green without downtime, roll back, self-host models from a pinned catalog; GitOps desired state when the owner opens it; Kubernetes and OpenTofu as stacks of the engine, never as product code; every workflow a thin caller of the `ci` kit; `infrax` is this engine extracted whole, minus the distribution table.
