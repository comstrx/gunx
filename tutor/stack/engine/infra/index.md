# engine/infra

The general engine of the work: one self-contained Bash 5 bundle that is at once the framework (`core` as a standard library, `config`, plug-and-play modules, the `@` macros), the tool of this repository (build, check, test, bench, fuzz, audit, the gates of every part, the `.github/` that travels, the extraction and the mirrors) and, tomorrow, the infrastructure (a Linux or macOS box from nothing to a running, monitored, backed-up stack, deployed without downtime, declared under a `[deploy]` scope of `infra.toml`, never as a meta of the tool). Written once for every product: `product/<project>/infra` customizes it with data and may extend it over its entry. The DSL is `{layer}:{domain}:{verb}` with no floating name; the only short hands are the `@` macros of the bundle.

## Layout

| `src/module/<name>/`    | plug-and-play modules, each `index.sh` (its facade), `src/*.sh` (flat verbs `module:<name>:*`, thin pipelines over core, config and the bundle; a module never calls a sibling module, `extract` calls `gate` from `extract/src/gate.sh` only) and `template/` (its data, never Bash): `bundle` (the framework itself: `build`, `pack`, `law`, `audit`, `expect`, `test`, `bench`, `fuzz`, `tool` = every pinned binary (fetch, run, pin; `@tool` and `@fetch`), `registry` = the command registry, `help`, `view`, `macro` = the global macros, `usage` = its own commands), `gate` (`part` = the parts and where each lives, `run` = the `gate` and `ci` commands, `changes` = what moved and what follows it, one chain file each `rust python go bun infra root`; `template/action.yml` = the engine as a composite action), `extract` (`git`, the tree, prepare, verify, `flows` = the `.github/` that travels, extract, place, push, sync); `pg mysql docker kubectl s3 cloudflare …` arrive the same way                                                                                                                                                                                                                                                                                                                 |
| `src/app/`              | three files and nothing else: `index.sh` (the entry: the bootstrap, `use app::boot`, then `app:root app:engine app:main`), `boot.sh` (`use core`, `use config`, `use module::bundle`, then `@use` of every other module and of the router: the order of the modules is the order of the commands in `help`, one flat list), `router.sh` (the global flags and `app:router:flags app:router:dispatch`: the one place that binds a command name to its handler through the registry). A command's declaration lives beside its code in `module/<name>/src/usage.sh`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `tests/ benches/ fuzz/` | flat folders discovered by suffix: `tests/<name>.test.sh` holds `test:<layer>:<domain>:*` (and `fixture:…`; the domain of a module is its name), `benches/<name>.bench.sh` holds `bench:…` printing quantiles and a `p50ns`, `fuzz/<name>.fuzz.sh` holds `fuzz:…` fed random bytes for a time budget; any other file there is ignored. A function in `config/`, `module/` or `app/` marked on the line above with `#cfg[test]`, `#cfg[bench]` or `#cfg[fuzz]` is discovered too and stripped from the release bundle; `core/` never carries one. Every domain of `src/` needs a `test:<layer>:<domain>:*` case or a `#cfg[test]` function (`check` refuses the tree otherwise); lab evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `target/`               | the artifacts of the checkout only: the bundles, the checksum, the bench baseline, a fuzz crash; ignored                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `.infra/`               | **the lab** (`[paths] cache`): everything the tool writes while it works, under the served root when that root is writable, else under `${TMPDIR}/.infra` (same layout, `config:paths:lab`); `tools/` the pinned binaries, `sbom/` the SBOM, `run/<stamp>.XXXX/` one session per run (its `pid` inside; temp files, test sandboxes, the `sync/<name>` trees; removed at exit unless kept; a session whose pid is dead is pruned by the next run), `lock/<name>/` the locks (`core:fs:lock`: a `mkdir` with the owner's pid, atomic on Linux and macOS, re-entrant, a dead owner is swept, a live one is waited for up to a budget); ignored, excluded from every mirror commit and refused by `verify` in a tree. Later `state/` carries what Kubernetes, Helm, Docker and Compose keep between runs. One rule: build in the session, verify, then `mv` into place on the same filesystem                                                                                                                                                                                                                                                                                                                                                                                                                                       |

Every layer has one `index.sh` facade and every module one; `core:load:use core::fs` (or `@use core::fs` above the bundle) loads `core/fs.sh`, `module::gate` loads `module/gate/index.sh`: a name resolves to the file, else to the folder's `index.sh`.

**Macros.** `module/bundle/src/macro.sh` is one thin file of global macros, loaded with the bundle before every other module: `@use @print @debug @info @succ @warn @err @usage @flag @global @eq @contains @absent @fails @errors @status @measure @tool @fetch`. They are a layer over the real verbs, never a replacement: `core:log:succ` or `module:bundle:usage:add` stay callable. The modules (`gate extract`), `app/` and the proofs write with them; `core/`, `config/` and the bundle module itself never do (they sit below them). ShellCheck cannot parse a `!` in a name, so the macro mark is the leading `@`.

## Laws

Enforced by `check` on every source and test file; nothing judges size or style:

- **Names:** every function is `{layer}:{domain}:{verb}` (a verb may carry more segments: `core:fs:file:read`, `module:bundle:law:check`); the layer and the domain come from the path (`src/core/fs.sh` → `core:fs`, `src/module/gate/src/run.sh` → `module:gate`, `src/app/index.sh` → `app`); `core`, `config` and `app` are flat, a module is `index.sh` + `src/` + `template/`; a proof file is named by its suffix and holds `test:* fixture:* bench:* fuzz:*` only; the only unprefixed functions are the `@` macros of `module/bundle/src/macro.sh`; a name is defined once; a macro is defined only there, called only above the bundle, detected only at command position.
- **Layer calls:** ranks `core < config < module < app < proofs`; a function calls its own layer and the layers below, never above; a called `{layer}:…` name must exist (a dynamic `"module:gate:${part}"` is checked to its prefix); `main.sh` calls `app:main` only; a module calls core, config, the bundle and itself, never a sibling; `core:toml:*` and `core:yaml:*` are reached through `core:parse:*` only. A tool combining two others belongs in app.
- **Portable:** outside `core/` the laws refuse `sed -i`, `shuf`, `readlink -f`, `date -d`, `grep -P`, a bare `timeout` and a bare `sudo` (call `core:fs:file:edit`, `core:list:shuffle`, `core:process:timeout`, `core:sys:sudo`); the `infra` and `root` rows of the gate matrix run on ubuntu and macos; `setup infra` installs the runtime commands of `[requires]` through the machine's package manager when they are missing, with `sudo -n` only.
- **I/O:** every network call runs through `core:process:io` (`RUN_TIMEOUT RUN_RETRIES RUN_BACKOFF`); every test runs under `TEST_TIMEOUT`; `bench --compare` fails past `BENCH_TOLERANCE` over the saved baseline.
- **Parts:** only `config/` and an env schema name a part; a source, test or template that writes a part's key prefix fails the check; tests run on their own fixture table; a proof that spells the owner is refused. The engine never names a product; a product's repository, name and paths are rows in the distribution table.
- **Values are data:** config resolves once with a fixed precedence: the defaults of `.env.example`, one env file of the served root (`.env.local`, else `.env`; a release build reads `.env.production`, else `.env`), the process environment, then the command line; the manifest is `infra.toml`, else `Infra.toml`; unknown keys fail atomically; nothing becomes executable.
- **Secrets:** names matching `PASSWORD SECRET TOKEN CREDENTIAL WEBHOOK_URL _KEY` are redacted everywhere; every integration turns on only when its keys exist, all or none, behind neutral keys.
- **The bundle** embeds every source and asset byte for byte into `target/`; a test compares each embedded asset with its file; the release bundle carries a checksum; it is slimmed (every `#cfg[…]` block, blank line and indentation of the sources gone, assets byte for byte) and never compressed: a compressed bundle would have to execute a decoded value, which the laws refuse, and ShellCheck, `audit` and a reader could no longer see it.
- **Standalone:** `install --alias gun` builds the release bundle and writes it as a command (`~/.local/bin` or `XDG_BIN_HOME`); run from any project root it reads that root's `infra.toml` and its git tree, so the same bundle serves this monorepo or any project shaped like it; `targets` and `sync` refuse to run while a target's part is missing under the root (every missing one named, nothing pushed), and refuse an empty table.
- **Sync:** the distribution is steps, each a verb, composed by commands. `prepare` lists the tree with `git ls-files` (nothing ignored travels), keeps by kind (engine: `engine/<x>`; fragment: `product/<p>/<f>`; tutor: `tutor/` minus `stack/product/*`; product: everything minus the other `product/*` and `tutor/stack/product/*`), flattens a tool to its root, adds the root governance files (`.*`, `LICENSE`, the four community docs with the monorepo's name renamed to the tool), cuts the changelog to the part's blocks and strips `[deps]` from `infrax`. `verify` refuses the monorepo's name and every product's name (read from `product/*`) in any tool, a `../` path into `engine/ product/ tutor/`, an env file and a tree without a manifest at its root; the renamed community docs are re-formatted by the pinned Prettier. `gates` runs the default gate chain of the part inside the prepared tree (`module:gate:one`, the one cross-module call, from `extract/src/gate.sh`), each type under `--timeout` (1800 s by default); a failure stops the steps after it. `extract NAME [--into DIR] [--gates]` (`NAME` is a row of `[deps]` or `product/<p>`) = prepare + verify (+ gates) into a kept session tree under `.infra/run/<stamp>/sync/<name>` or `DIR`; `place NAME DIR` = extract, then write into a local folder keeping its `.git`; `push NAME [--branch B] [--repository R] [--dry-run]` = prepare, then `module:extract:git` does the rest: the address of the table (or `--repository`) is resolved by `core:git:resolve` (`name` → the owner and host of the current tree's `origin`; `owner/name` → that host; `host/owner/name`, an `https://`, `ssh://` or `git@host:` URL, or an absolute path, taken as given); a repository that does not exist is created private (`gh repo create` when `gh` is logged in and no `GIT_TOKEN`, else the GitHub API with `GIT_TOKEN`; a path becomes a bare repository); the branch is cloned (an orphan branch when it is new), emptied but `.git`, filled with the tree, verified and gated in place, committed `Track <tag>` (the target's `tag` when it is a semver, else the exact `v*` tag of HEAD, else its short sha) on top of the mirror's history (no commit when nothing changed, never a force push), tagged (an existing tag refuses), then pushed; `--dry-run` stops right before the push, authenticated by `GIT_TOKEN` (or the token of the logged-in `gh`, never on argv) and committed as `GIT_CONFIG_NAME <GIT_CONFIG_EMAIL>` or, when either is unset, as the author of the last commit of the source tree; `sync` pushes every target of `[deps]`, the infra engine first.
- **`.github/` travels:** a tool receives `CODEOWNERS`, the issue and pull request templates, `labels.yml` and `labeler.yml` (every part label dropped, the generic ones kept), `dependabot.yml` (the actions entry and the tool's own ecosystem entry moved to `/`, prefixes `deps`, the monorepo header gone) and every workflow (`ci daily release labels labeler`). `module:extract:flows` rewrites them in place through `core:parse:yaml:*`: `paths:` filters erased, the job that runs `infra sync` pruned, `*-version-file: engine/<x>/<file>` pointed at the root file when the tool has it and dropped otherwise, empty `with:` blocks removed, `uses: $/engine/infra/src/module/gate/template` rewritten to `<owner>/infrax/src/module/gate/template@<sha> # <tag>` (the sha of the infrax mirror at the release tag, else its `main`; `$/src/module/gate/template` inside infrax itself) and that action allowed in the tool's `.zizmor.yml`; the monorepo's name (the name of the root's `origin`, never a literal) becomes the tool's name in `.github/**` and the community docs; `verify` then refuses any `engine/ product/ tutor/` path or `main.sh` under `.github/`. A product keeps `.github/` whole, minus the Dependabot entries of the other products. Every extracted tool passes actionlint and zizmor (pedantic, low) offline.
- **Gate:** `gate [--part P] [--product X] [--type T] [--timeout S] [--pass]` gates every part present under the root, or one (`rust python go bun infra api web mobile desktop tutor root`), each in its folder (`engine/<x>`, `tutor`, the root, `product/<X>/<fragment>`; every product when `--product` is absent; an extracted tool is gated as the part of its manifest plus `root`). The types are `deps check lint test safety audit quality security twins bench fuzz`; `--type` is `default` (all but `bench` and `fuzz`), `all`, or a comma list; `audit` and `fuzz` belong to the engines (`GATE_ENGINE_ONLY`) and `twins` to the fragments (`GATE_FRAGMENT_ONLY`): it hashes the shared files of one product's surfaces (`GATE_TWINS` across `web mobile desktop`, `GATE_TWINS_DOM` across `web desktop`) and fails on drift; a type a part does not have is skipped, and a `deps` left alone by the skips with it. Every type is one function `module:gate:<chain>:<type>` in `gate/src/<chain>.sh` with the full command inlined, never a call into a part's own runner; the `bun` chain prefers a part's own `deps check lint test audit` scripts when its manifest has them, never its `gate`, and runs `bun run link` after deps and `bun run build` after check when the part declares them; `api` picks its chain by manifest (`pyproject.toml` python, `Cargo.toml` rust, `go.work` or `go.mod` go; never bun), `web mobile desktop` are bun, `tutor` and `root` share one file. Each type runs in a subshell under `--timeout` (1800 s by default; a fuzz splits nine tenths of it over its targets, `GATE_SECONDS`), a timeout is reported as such; `--pass` reports a failure and goes on. `ci [--base REF] [--all]` takes the same flags and gates what moved since the ref (`--base`, else `CI_BASE`, else `HEAD~1`) and everything built on it: an engine when its folder moved, `tutor`, `root` when `engine/infra` or anything outside the engines, the fragments and `tutor` moved, a product fragment when it was touched, when `engine/infra` moved or when the engine of its manifest moved. `--all` or `CI_ALL=true` gates everything; so does a default ref the tree does not have, with a warning, while a `--base` it does not have is an error; nothing to gate is a success. `changes` takes the same selection and runs nothing: one row per gate with its count of changed files or `follows what it builds on`, the files themselves under `--part`. A workflow carries a fixed matrix of the parts, each row calling `ci --part`; the plan is tested offline.
- **Extension:** a product's `src/main.sh` sources this engine's `src/main.sh` with `INFRA_ENTRY=library` (no dispatch), then defines its own `app/` over the same core, config and modules under the same laws; the product's `check` runs the engine's laws on the product's files too.

## Gate

`infra gate --part infra` = the runtime packages + `fetch shellcheck` inside the gated tree · `check` · `test` · `test --shuffle` (safety) · `audit`; `bench` and `fuzz` by name. Before `infra` is installed: `bash engine/infra/src/main.sh --root . gate --part infra`.

## How to add

- **A core verb:** `core:<domain>:<verb>` in `core/<domain>.sh`, general as a standard library, silent on success, `core:error:fail` on failure, a `test:core:<domain>:*` case in `tests/`; never a proof inside `core/`.
- **A module:** `module/<name>/index.sh` that `use`s `module/<name>/src/*.sh` with its data under `module/<name>/template/`; a `test:module:<name>:*` case; nothing else changes.
- **A command:** one line in the module's `src/usage.sh`: `@usage NAME HANDLER 'usage' 'summary'` (+ `@flag NAME '--flag VALUE' 'summary'`); the help, the flags and the dispatch follow; a handler is a module verb.
- **A gate type or chain:** one function `module:gate:<chain>:<type>` in `gate/src/<chain>.sh`; `run` discovers it.
- **A sync target:** one line in `[deps]` (`name = { type, path, repo, deps = [...] }`; `tag` only when it is not `inherit`), a product's `repo` in its own `[meta]`; `sync` reads the line and runs the same `prepare → verify → place|push`.

## Direction

From the needle to the rocket by one bundle and one command: install the newest tools, configure the services, run and monitor them, manage ips, domains and TLS, back up and restore with point-in-time recovery, roll blue/green without downtime, roll back, self-host models from a pinned catalog; GitOps desired state when the owner opens it; Kubernetes and OpenTofu as stacks of the engine, never as product code; `infrax` is this engine extracted whole, minus the distribution table. `prepare` reads the `deps` rows the day a tool references its engine by tag. The laws that arrive with the stacks:

- **Delivery:** images are built from the repository root, scanned and pinned by digest; deploys are blue/green with draining, a verify window and automatic rollback; migrations are a release of their own, never at peak and never in the same breath as the code deploy; backups with point-in-time recovery and a rehearsed restore before every release; the api reachable only from the edge; only content-hashed files served immutable; every alert has an owner and a recovery action.
- **Env ownership:** each product part owns its env file and nothing crosses; the engine receives it, pins it and mounts it read-only, forcing only what it owns (bind address, port, storage root, migrations off, release name). Application policy belongs to the app env and the app enforces it.
