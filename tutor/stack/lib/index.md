# Libraries

## Contract

Select the implementation-specific lesson from explicit context or verified manifests.

## Structure

The local directory name is a skill identifier; it need not match an upstream package name.

## Rules

Choose the relevant library from the task and integration context. A library lesson does not add an unrelated dependency to every engine.
A part may supply its surface-library choice through an engine route; this is knowledge selection, not an engine import.
If no library applies, the engine goes directly to the language dispatcher. Do not choose a library to fill an empty field.
An unregistered required library is a missing knowledge contract; identify it without pretending a different lesson covers it.

## Proof

Library choice is evidenced; language learning completes; no product logic appears here.

## Sources

Each child identifies its official upstream or the locally owned framework source.
